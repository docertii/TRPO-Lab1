Практические операции выполнены командами Git в Windows. В методических указаниях показан интерфейс GitExtensions; здесь использованы соответствующие команды Git. GitHub использован вместо GitLab с разрешения преподавателя.

## История

- `master`: создание и изменение notes.txt, слияние с разрешением конфликта, cherry-pick, revert, шаблон и проверка сообщений.
- `feature`: отдельное изменение текста и переносимый коммит.
- `rebase-demo`: изменение, перенесённое на обновлённый master.
- `reset-soft`, `reset-mixed`, `reset-hard`: ветки трёх опытов сброса.
- Метки `before-rebase`, `before-revert`, `before-reset-*` сохраняют промежуточные версии.

Просмотр всей истории: `git log --all --graph --decorate --oneline`.
Протоколы промежуточных состояний находятся в `evidence/`.
Коммиты первых опытов содержат технический локальный адрес example.invalid; для дальнейших коммитов настроен noreply-адрес GitHub. Существующая история сохранена без переписывания.

## Проверка сообщений коммита

Windows: `git config core.hooksPath .githooks/windows`
Linux: `git config core.hooksPath .githooks`
Шаблон: `git config commit.template .gitmessage`

Заголовок содержит 1–72 символа, вторая строка пустая, непустые строки описания начинаются с четырёх пробелов и имеют длину не более 100 символов.
Для Windows включён исходный код ValidateMessage.cs и собранный commit-msg.exe; для Linux — shell hook.
Настройки .git/config не переносятся при клонировании: команды настройки надо выполнить в новой копии.

## Патч

`feature.patch` переносит отдельную строку из ветки feature. Проверка применимости: `git apply --check feature.patch`.
Патч сохраняет изменения файла, но применение через git apply само по себе не создаёт коммит.
